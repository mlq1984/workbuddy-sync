# OCR 常见问题

排查顺序：`engines` 看引擎 → 回执看引擎与行数 → 换引擎对比 → 再看图片本身。

## 一、按现象排查

### 「Windows 系统没有安装任何 OCR 语言包」

WinRT 引擎可用但语言列表为空。两种处理：

1. 安装语言包：`设置 → 时间和语言 → 语言和区域 → 添加语言 → 语言选项 → 可选语言功能 → 光学字符识别`；
   企业环境用 `Add-WindowsCapability -Online -Name "Language.OCR~~~zh-CN~0.0.1.0"`。
2. 改用 tesseract：`--engine tesseract`（需先装 tesseract 与中文语言包）。

**不要**在语言包缺失时反复重试同一引擎，也不要谎称已识别。

### 中文识别效果差 / 识别成乱码

- tesseract：确认装了中文语言包（`tesseract --list-langs` 里要有 `chi_sim`）；
  没装时本技能会降级到 `eng`，中文必然很差。
- WinRT：确认语言包是中文（简繁分别对应 `zh-Hans` / `zh-Hant`）。
- Vision：传 `--lang zh-Hans` 明确指定，不要依赖自动。
- 图片本身太小/太糊时，先放大或换原图，别指望引擎"猜"。

### 什么都没有识别出来

按顺序检查：

1. 图片里真的有文字吗（纯照片、纯图形）；
2. 文字是否太小（< 12px 高基本无解）；
3. 语言是否匹配（中文图却只装了英文包）；
4. 是否是手写/艺术字（三个引擎都不可靠）；
5. 换引擎试一次（`--engine tesseract`），并把两个引擎的结果一起给用户参考。

如实说明原因，**不要**编造内容填充结果。

### 表格识别后串行

- 试 `--engine tesseract --psm 6`（把整页当单块文本）；
- 复杂表格建议：先 OCR 拿到文字，再由模型按语义重组表格结构，并明确告知这是重组结果；
- 有清晰边框线的表格，也可以先用文档转换技能处理原始电子表格（比 OCR 靠谱得多）。

### PDF 识别不了

本技能的图片引擎不直接吃 PDF 多页。处理方式：

1. 若 PDF 自带文本层 → 用文档转换技能直接抽取文字（又快又准）；
2. 若是扫描件 → 先把 PDF 每页转成 PNG，再逐页 OCR；
3. 交付时说明这是逐页识别的结果，页码信息会保留在 `page` 字段里。

### HTML 结果打开后图片不显示

默认会把图片内联成 `data:` URI（单文件）。若用了 `--no-embed`，HTML 会引用同目录的图片文件，
移动 HTML 时要带上原图。给用户交付时**推荐默认的内联模式**。

### HTML 里点复制没反应

- 浏览器在 `file://` 下不允许 `navigator.clipboard`，本技能已内置 `execCommand` 回退；
- 若在极老的浏览器（IE）里仍失败，会弹提示要求手动选择文本——属预期降级；
- 某些企业策略会禁用剪贴板 API，此时用「查看结构化 JSON」按钮配合手动复制。

### 坐标（box）不准 / 高亮位置偏了

- 三个引擎的坐标系已被统一成**归一化 + 左上原点**；Vision 原生是左下原点，已在脚本里换算；
- 若高亮整体偏移，通常是图片被浏览器缩放导致的显示误差，检查 HTML 是否被外部 CSS 影响；
- WinRT 的行框是由词框合并而来，与视觉行可能有细微差异。

## 二、性能建议

| 情况 | 建议 |
|---|---|
| 大图（> 4000px） | 先缩放到 2000~3000px 宽再识别，速度更快且精度基本不降 |
| 多页文档 | 逐页识别并合并，不要一次塞进超大图 |
| 批量截图 | 用 tesseract 更快；系统 OCR 在单张上更快但启动开销固定 |
| 中英混排 | Windows 上 WinRT 只支持单语言，建议改用 tesseract `--lang zh-Hans,en-US` |

## 三、复现与反馈

1. `ocr_cli.py engines` 的完整输出（引擎、路径、版本、语言列表）；
2. 完整命令与回执（引擎名、行数、语言）；
3. 图片的尺寸与格式（以及是否可提供脱敏样张）；
4. 期望识别的语言与实际语言。
