## 6.3 环境预检协议

每个阶段开始前自动执行环境预检，确保所需能力可用。

**CLI（复盘 P0）**：`node scripts/bookwriter.mjs run scripts/env-preflight.mjs`（Node 版本、Windows 下 `powershell -File` 变量探针；**禁止**依赖 `powershell -Command` 内联 `$变量`，宿主可能先吃掉 `$`）。

### 预检清单

| 检查项 | 验证方式 | 失败处理 |
|--------|----------|----------|
| Node.js | `node -v` / env-preflight | 无法运行脚本时中止并提示安装 |
| PowerShell（Windows） | **仅** `-File` 调用 `.ps1`；勿用 `-Command` 传 `$` | 字数/词频改用 `node` 脚本 |
| 联网能力 | 执行一次test搜索 | 降级为本地知识库 |
| Mermaid CDN | 检测unpkg/jsdelivr连通性 | 使用本地mermaid.js |
| 文件系统 | 测试写入权限 | 提示权限问题 |
| 可选委派 | 核对当前会话工具列表、参数和结果方式 | 未提供或未确认时由当前助手串行执行 |
| 任务交接 | 核对本会话是否提供任务状态/回传机制 | 未提供时使用项目内获准文件记录，标明未观测状态 |
| 进度更新 | 使用当前会话实际提供的进度能力 | 未提供时按里程碑向用户汇报，不伪造心跳 |

### 6.3.1 工具不可用时的降级（禁止心算字数）

| 能力 | 优先 | 降级 | **禁止** |
|------|------|------|----------|
| 字数/字符统计 | `node` 读文件 + `length` / `expansion-word-verify` | 宿主 `read_file` 后人工点数 | 仅报模型估算字数 |
| 快速扫描 | `powershell -File scripts/quick-scan.ps1` | `node scripts/bookwriter.mjs run scripts/quality-auditor.mjs` | `powershell -Command` 内联含 `$` 的命令 |
| 章节合并 | `node scripts/bookwriter.mjs run scripts/merge-chapters.mjs` | 手工复制粘贴 | 依赖 bash 的 `$OUTPUT` 片段（Windows 常失败） |

### 预检执行时机

- S1开始前（定位阶段）
- S3开始前（写作阶段）
- S4开始前（审核阶段）

### 预检输出格式

```
🔍 环境预检
  联网搜索：✅ 可用
  Mermaid CDN：✅ unpkg可用
  文件写入：✅ 可用
  原生委派：已确认可用 / 未提供
  任务状态：有真实回执 / 文件记录 / 未知
  ✅ 环境就绪，开始执行
```

### 环境预检与心跳监控的协同关系

- 预检通过 → 使用本会话确实提供的可选能力；委派仍需用户任务允许
- 预检失败但可降级 → 由当前助手串行执行并标明未观测范围
- 预检失败无法降级 → 中断执行，提示用户修复

## 6.4 长任务检查点、超时与恢复

本节描述当前Skill会话能履行的任务管理方法，不假设宿主提供Agent Team、成员心跳、消息或强制关闭接口。主持职责见[主持方法](fbs-team-lead.md)，写作职责见[写作方法](fbs-writer.md)。未使用真实委派时，不创建虚构成员状态、心跳包或关闭回执。

### 6.4.1 进度与检查点

每个有界任务记录开始时间、输入与输出路径、最近一次实际读回的文件状态、已完成内容、阻塞原因和下一步。若当前会话实际提供且可确认的进度工具，按其真实参数调用；否则在里程碑或约定等待上限到达时向用户汇报，不编造百分比/成员响应。

### 6.4.2 超时、取消与partial回收

| 情况 | 当前会话处理 |
|------|--------------|
| 子任务或工具到达超时 | 停止等待，保留已读回结果，标记partial/unknown并提供接续位置 |
| 当前会话存在原生取消接口 | 仅在目标任务句柄明确且工具可用时，按其当前文档取消并读回状态 |
| 写入了独占临时文件 | 先只读检查文件和差异，保留源稿；按用户授权决定合并或留作partial |
| 无法确认任务是否停止 | 不重放有写副作用的动作，不声称已关闭；保留当前状态并向用户说明未知 |

不得递归清理未知目录，不得强制终止宿主进程或其他会话。恢复时先核验文件真值和写入范围，再续做。

### 6.4.3 可选委派与文件交接

只有当本会话实际列出原生委派工具、参数/回传合同可确认且用户任务允许时，才拆分子任务。分工前指定独占输入/输出、共享上下文、停止条件和验收人；跨任务共享词表、章节台账与最终合并由主持职责统一负责。没有真实通信工具时，通过项目内已授权的简短交接文件和读回续接；未有工具回执或文件读回不记为成员已完成。
## 6.5 可靠性设计原则（2026最佳实践）

**硬性限制**（防止Agent失控，**目标口径**）：

| 限制类型 | 阈值 | 触发动作 |
|----------|------|---------|
| 单次工具调用超时 | 30秒 | 重试1次，失败则降级 |
| 连续失败次数 | 3次 | 中断并报告 |
| 单Agent最大运行时长 | 4小时 | 自动保存进度，请求用户确认续行 |
| 内存使用 | >80% | 触发GC，必要时分批处理 |
| 文件写入大小 | 单次>10MB | 分批写入 |

**故障分类与响应策略**：

| 故障类型 | 严重程度 | 响应策略 |
|----------|---------|---------|
| 联网失败 | 中 | 降级本地知识库，继续执行 |
| 工具调用失败 | 中 | 重试+降级 |
| 成员失联 | 高 | 尝试重连，超时强制关闭 |
| 文件写入失败 | 高 | 立即停止，提示用户修复磁盘 |
| 状态机异常 | 严重 | 回滚到上一安全状态 |

**降级机制**：

```
降级层级（从优先到兜底）：
L1: 正常执行（所有能力可用）
L2: 当前会话未提供委派工具时，串行执行
L3: 禁用联网（网络失败时，使用本地知识）
L4: 单章模式（大文件分批处理）
L5: 仅输出骨架（极端降级，保证交付）
```

**状态终端定义**：

| 终端状态 | 含义 | 后续动作 |
|---------|------|---------|
| DELIVER | 成功交付 | 归档，等待用户反馈 |
| ABORT | 主动中止 | 保存进度，提示恢复方式 |
| ERROR | 错误终止 | 输出错误报告，建议修复步骤 |
| TIMEOUT | 超时终止 | 保存已完成内容，提示续行 |

### 6.5.1 宿主能力、进度与写盘核验（交付审核约束）

**联网约束**（宿主侧）：

```
规则：联网查证仅使用当前会话实际提供且用户任务允许的检索工具
降级：无工具、超时或来源无法读回时，明确标记未核实/模型知识，不写成已联网证据
审核要求：影响结论的引用均须有可读来源和时点；工具调用自述不替代来源读回
```

**进度约束**（宿主侧）：

```
规则：若本会话提供进度回报工具，按其真实接口记录；否则在里程碑向用户汇报
格式：报告实际完成、下一步、阻塞和partial路径，不虚构成员心跳或百分比
未知：不能读取子任务状态时标为unknown，不将静默或超时推断为成员失败/已关闭
```

**写盘约束**（宿主侧）：

```
规则：写入只能使用当前会话实际提供且授权的文件工具或dispatcher
禁止：仅凭模型/成员回复声称文件已写入
验证：对目标文件实际读回，核对路径、内容范围和用户手改保护
审核：交付前检查指定产物存在且可读；未知保持未知
```

**交付前审核清单**：

```
☐ 所有联网引用均有工具调用记录
☐ 所有写盘操作均有write_to_file记录
☐ 文件确实存在（通过read_file或list_files验证）
☐ 任务状态来自实际工具回执或文件读回；缺失部分标unknown
☐ 状态机正确转移（无跳步）
```
