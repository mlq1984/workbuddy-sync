# 股票研究报告

本技能**仅用于单只股票**。每次调用只能研究一只标的；接口与脚本均按单标的设计，不支持一次生成多只股票的研究报告。

将用户原始问句作为 `query` 调用股票研究接口，生成单只股票的完整研究报告。不要自行编造实体识别结果、研究数据或报告内容。

## 使用边界

- **仅限单标的**：只用于单只股票的完整公司研究、基本面深度分析或一页纸报告。
- 用户只问实时价格、K线、单项财务指标或新闻时，改用行情、查数或资讯技能。
- 用户要求多股比较、筛选或股票池时，改用比较或选股技能。
- 用户研究 ETF、可转债时，使用对应专项技能。
- 用户没有提供可识别的股票名称或代码时，先请用户补充，不要调用接口。
- 同一问句包含多只股票且未明确主体时，**先请用户确认一只**，再只对用户确认的那一只调用本技能；不要自行选择、不要拆分多次调用、不要并行处理多只。

| 退出码 | 含义 | 处理方式 |
|---|---|---|
| `0` | 生成成功 | 读取报告预览、分享链接及附件路径 |
| `10` | 需要授权 | 展示一次 `authUrl` 并停止本轮调用；授权完成后让用户重新发送原指令 |
| `2` | 网络或业务错误 | 返回失败原因，不编造报告 |
| `1` | 缺少 query/stdin | 请用户补充股票名称或代码 |

## 超时与重复调用

脚本内部已实现有限次退避重试（最多 2 次，退避 30s / 90s），单次调用最长等待 1200 秒，超过该时长即判定为超时失败；模型不得因失败重复调用同一 `query`，同一 `query` 累计调用不超过 2 次。若命令超时被中断或返回非 0 退出码，立即停止本轮并按失败话术输出，禁止后台执行、禁止改写 `query` 或更换标的重试。


## 调用

**依赖安装（调用脚本前完成一次即可）：**

本版本**不解析 Word 内嵌图片表**，仅抽取 PDF/Word 文本层与 Word 原生表格。依赖很轻：

```bash
pip install -r requirements.txt
```

要点：

- 必装：`pypdf`、`httpx`（详见 `requirements.txt`）。
- 上游若把「主要财务指标」「一致预测」「分板块」「研发实力」等做成内嵌图，这些章节在 `fullContent` 中可能只剩标题；**不要编造表格数字**，引导用户打开附件 PDF/Word 查看完整版式。

```bash
python3 scripts/get_data.py --query "生成东方财富的股票研究报告"
```

接口响应可能较慢。必须在当前会话同步等待命令结束，禁止后台执行或承诺稍后汇报；命令超时或被中断时按「超时与重复调用」一节处理，不得重复调用同一 `query`。

授权流程见下方“授权”。正常调用时直接执行业务脚本，不要先单独运行 `scripts/auth.py ensure`。

参数：

- `--query`：用户原始问句；也可由 stdin 传入。
- `--no-save`：不保存 PDF、Word 附件。
- `--debug`：在运行目录保存原始接口响应。

## 报告范围

报告通常覆盖公司近况、核心研究观点、公司简介、业务拆分、产销链、研发实力、财务分析、盈利预测与估值、风险提示。没有可靠数据的章节可能省略。

## 返回字段

- `title`：报告标题。
- `articleId`：报告文章 ID。
- `shareUrl`：分享链接。
- `content`：接口返回的报告预览（仅作回退用）。
- `fullContent`：从 PDF/Word 附件抽取并整理为可渲染 Markdown 的完整报告正文（含标题层级、表格分隔行、Word 加粗映射为 `**粗体**`），是模型最终输出的唯一来源。
- `fullContentSource`：`fullContent` 的来源，取值 `word` / `pdf` / `preview`。
- `files`：本地附件的**完整绝对路径**（脚本返回 `path.resolve()` 的结果）。文件名使用接口返回的 `title`（如 `东方财富(300059.SZ)股票研究.pdf`、`腾讯控股(00700.HK)股票研究.docx`、`苹果(AAPL.US)股票研究.pdf`），非法路径字符会替换为 `_`；`title` 为空时回退 `articleId`。`files.pdf` / `files.word` 必须原样使用，不得缩短为文件名。
- `mediaDir`：本版本固定为空字符串（不落盘内嵌图）。
- `referenceCount`：接口返回的溯源条目数量。
- `ok`、`message`：执行状态与失败原因。
- `need_auth`：为 `true` 时表示需要用户授权。
- `authUrl`：扫码授权链接，仅在需要授权时返回。
- `apiKeyUrl`：手动获取 API Key 页面，仅在需要授权时作为兜底返回。
- `auth_message`：授权提示信息。

## 用户可见输出

`fullContent` 已由脚本整理为**可渲染的 Markdown**（标题层级、表格分隔行、段落空行）。模型最终输出必须原样照排这份 Markdown，禁止缩写、改写、重写、摘要、润色；也不要把表格转成叙述、不要删去表格行、不要合并段落。`content` 仅为预览，仅当 `fullContent` 为空时才作为回退使用。

输出硬性要求：

1. 以 Markdown 正文直接输出，便于 WorkBuddy / 聊天窗口渲染；**禁止**把整篇报告包进 \`\`\` 代码块。
2. 报告标题行：`# {title}`（若 `fullContent` 首行已是同一标题，可不再重复）。
3. 空行后，原样输出 `fullContent` 全部内容。
4. 在 `fullContent` 之后另起一节，列出附件路径与分享链接。按实际存在的附件输出对应行；没有附件时写“完整报告：暂无可用附件”。

附件路径必须使用脚本返回的 `files.pdf` / `files.word` **完整绝对路径原样照排**，禁止只输出文件名、禁止截断目录、禁止改写盘符或分隔符、禁止加引号包裹。若该字段为空字符串，则对应附件行写“暂无可用附件”。

```text
# {title}

{fullContent}

**附件：**
- 📄 PDF版完整报告：{files.pdf}
- 📝 Word版完整报告：{files.word}

**分享链接：**
{shareUrl}
```

若 `fullContent` 为空且 `content` 也为空，直接停止并说明失败。不要读取附件后另行拼接或生成另一份报告，也不要调用其他数据源拼接替代性报告。内容由 AI 生成，仅供研究参考，不构成投资建议或收益承诺。

## 常见问题

**本技能支持一次分析多只股票吗？**  
→ 不支持。本技能只能用于单标的。问句中出现多只股票时，先列出识别到的标的请用户确认一只，再只对确认的那一只调用；不要自行挑一只，也不要拆成多次调用。

**出现 `need_auth: true` 怎么办？**  
→ 展示脚本输出的 `authUrl` 让用户扫码授权；若无法扫码，再提供 `apiKeyUrl`。授权完成后请用户重新发送原指令，不要轮询、等待或追问是否完成。

**为什么有的章节只有标题没有表格？**  
→ 本版本不解析 Word 内嵌图片。若该章上游是图片表/图表，`fullContent` 可能只有标题；请打开附件 PDF/Word 查看完整表格，不要编造数字。若 PDF 文本层含有该表，脚本会优先用 PDF 抽取结果。

**分板块业务情况表格错位怎么办？**  
→ 该表「业务板块」列在 Word 原生表里常为纵向合并单元格。脚本会对这类**原生文本表**做结构修复：把板块名补全到每个指标行。图片表不处理。

**接口超时或失败后可以重新调用吗？**  
→ 不可以自动重试。脚本内部已做有限次退避重试（最多 2 次，30s / 90s），单次最长等待 1200 秒；同一 `query` 累计调用不超过 2 次，且仅在上游返回可重试信号（5xx / 连接中断 / 限流）或用户主动要求时才允许再次调用，超时或被中断一律停止本轮并输出失败话术。

**注意：股票研究报告接口响应时间较久，请耐心等待。**  
→ 在当前会话中同步等待到命令完成，拿到 stdout 的结果后再继续输出，禁止后台执行或承诺稍后汇报。

**异常场景**

| 异常场景 | 处理方式 |
|---|---|
| 接口调用超时 / 502 | 原样返回失败原因，不编造报告；同一 `query` 不再重复调用（脚本内已退避重试 2 次） |
| 命令超时被中断 / 无输出无退出码 | 视为失败，按失败话术输出后结束本轮，禁止后台执行或改写 `query` 重试 |
| 接口返回空数据 | 返回失败说明，请用户核对股票名称或代码 |
| 实体无法识别 | 请用户补充可识别的股票名称或代码后再调用 |
| 多标的且未确认主体 | 先请用户确认一只，确认前不调用接口 |
| 关键章节为图片表、正文缺表 | 输出已抽取正文，并提示打开附件 PDF/Word；不要编造表格 |
| 需要授权（退出码 `10` / `need_auth: true`） | 展示一次 `authUrl`；授权完成后让用户重新发送原指令 |
| `EM_API_KEY` 失效 / 401 / 403 | 按脚本提示清理失效凭据并重新授权；不要编造报告 |

## 授权

本 Skill 依赖 `EM_API_KEY`，完整流程遵循 [授权协议](references/auth_protocol.md)。调用前按以下顺序处理凭据：

1. 先复用平台私有跨会话存储中的 `EM_API_KEY`。
2. 若平台凭据不可用，再安全检查 `~/.mx-skills/em_api_key` 是否存在且非空；不要打印文件内容。
3. 若两级缓存都没有凭据，优先调用东方财富妙想 MCP 的 `mx_get_user_api_key` 获取当前登录用户的 API Key，并写入平台私有存储和 `~/.mx-skills/em_api_key`。
4. 仅当 `mx_get_user_api_key` 不可用、调用失败或未返回有效 `apiKey` 时，才直接运行脚本，让脚本进入内置扫码授权兜底。

不要先单独运行 `scripts/auth.py ensure`；该命令仅用于调试。处理 `apiKey` 时不得向用户展示、复述、写入日志或拼进 shell 命令。
