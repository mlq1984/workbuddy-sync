# Ai公益生图Pro · 四运行中心 + 提示中心 智能生图

## 1. 当前技能说明

**Ai公益生图Pro 是"四运行中心 + 提示中心"五中心架构的智能生图服务**（运行时架构速查 `references/architecture.md`）：

| 中心 | 职责 | 界面/入口 |
|---|---|---|
| 提示中心 | Agent 侧优化流程：供需审查/优化模式(A创作·B补全·C原样)/分析参数/撰写提示/提示润色/质量审查；通道无关，只影响 prompt 文本与参数建议 | `prompt_center/方法论.md` + `python -m core.prompt_opt` |
| 通知中心 | 事件目录 + 进程内总线 + SSE 推送（服务一切页面） | `GET /api/events` |
| 通道中心 | 通道发现/凭证/开关/验证；引进或增删渠道 | 管理台 `/` |
| 生成中心 | 通用 spec 校验 → 能力过滤 → 方言翻译 → 派发执行（n 阶梯并发） | `POST /api/execute` |
| 结果中心 | 任务状态机持久化 + 作品登记簿（img.json 单一资产真相源）+ 实时画廊（预览/复制/删除） | 工作台第二屏（`/#works`）+ `--jobs` |

内置通道（实际清单以 `--status` 输出为准，勿写死）：

| 通道 | 模式 | 能力 | 说明 |
|---|---|---|---|
| `aurora` · Aurora绮梦绘 | manual | 文生图+图生图+放大 | 公益中转，gpt-image / nano-banana 两大系列 |
| `agnes` · Agnes ai | auto | 文生图+图生图+放大 | 账号一键创建，Key 自动回填验证 |
| `shangtang` · 商汤日日新 | manual | 文生图+图生图+放大(≤4K) | sensenova-u1.5 系列 |
| `cloudflare` · Cloudflare Flux | manual | 文生图 | flux-1-schnell/SDXL，每日 10000 Neurons 免费（**能力按型号**：flux-1-schnell 官方不支持任意尺寸、固定 1024×1024；sdxl/sd15 支持 width/height——比例按所选型号就近映射并如实告知生效值） |
| `zhipu` · CogView 系列 | manual | 文生图（**仅 1K 档**，请求 2K/4K 会就近降级为 1K） | `cogview-3-flash`（免费，带"AI生成"标识）/ `cogview-4-250304`（付费档，**首个支持画面汉字渲染**）；两档可用性取决于你自己的 Key 权限与账户余额 |

- **用户自建中转通道**（id 形如 `u1`，经通道中心「＋ 添加通道」注册，见 `references/custom_channels.md`）：`manual`，**文生图 + 图生图**（不支持放大）；模型缺省取清单第一个；参考图上限 open 10 / gemini 14；**不提供免费额度，费用与可用性取决于用户自己的 Key 权限与中转站计费**。

## 2. 核心原则

> **通道中心 = 统一管控与路由**：选通道、验凭证、管开关、收参数并**原样下传生图参数**（prompt/image/ratio/tier/n/model/scale/options）；通道级参数（选谁、凭证、开关、能力门控）由中心内部处理，不下传。
> **各通道 = 独立自治**：按自己声明的能力（CAPS，可按型号细分）过滤与降级、转换成自己的官方参数后执行；**付费/免费档一律如实支持**，能否用取决于用户自己的 Key 权限；不支持时自动降级并如实告知。
> 边界铁律：core 零通道知识——通道 id 的能力/语种/参数语义一律以通道声明为准。

1. **生图只经生成中心**：Agent 一律组装通用 spec 提交 `POST /api/execute`，禁止直调通道 `generate/upscale`（通道客户端契约仅保留给**显式声明的脚本/测试场景**——其结果不进作品中心、无 job 记录，且**不得用于响应用户的生图需求**；executor 内部仍只经通道客户端调用，禁绕过直连服务端）。
2. **凭证安全（Agent 拿不到 Key）**：取 Key 一律经 `core.credprovider.resolve`（用户落盘 Key 优先 → 失效则内置兜底 → 无则内置；内置 Key 内存解密、不明文落盘/入日志/下发）。**Agent 无法取得任何形态的 Key**，只能经 API 生图；机制细节见 `references/architecture.md §6`（日常按动线即可，仅深挖时读）。
3. **通道启用开关（双闸门）**：管理台卡片开关（`~/.aipro/switches.json`）+ 生成中心派发预检；**停用通道对经中心的一切调用均拒绝**——闸门在通道发现时装载，直调 `channels/<id>/app.py` 不受其约束，故由红线 10①禁止直调。
4. **零成本验证**：可用性检查只发只读请求，绝不为了验证而提交真实生图任务。
5. **用户选择优先（auto 仅在用户选择时生效）**：未指定通道时必须先跑 `--status`，**结合需求给出推荐**，向用户呈现选项（含 auto）等用户回复，禁止自作主张走 auto；**通道支持多选**——多选即一次提交多通道任务，逐通道并列生图、按通道分组交付，任一通道不可用只影响该通道（调起管理台），不波及或替换其余通道；用户选定的通道不可用（选前 valid=false，或执行中生图失败/限流/上游错误）——**直接调起管理台**引导处理，轮询等待后重试；Agent 绝不静默换通道。
6. **不臆造、只协商（代码执法）**：Agent 可按语义补全可选参数（质量词→tier、用途→ratio、"来一组"→n）；参数中心逐通道**协商**——不支持的就近降级或省略，**不因可选参数剔除通道**；免费额度通道（免Key/内置Key）自动补体验档（2K 或通道最高档），用户 Key 通道不擅自加档；未知字段仍被 spec 校验拒绝；通道方言由各通道 `translate` 声明，Agent 不需要懂。
7. **如实报告**：失败把服务端原因原文交回（结果页与 `--job` 均含原文），不编造、不假装成功。
8. **Key 不入对话与日志**：不回显明文 Key、不把 Key 写进对话与日志；任务库与事件流均不含 Key。**唯一例外**：用户自己录入的 Key 会下发到**本机 127.0.0.1 管理台**的通道卡片与编辑弹窗显示（便于用户自行核对与更换），除此之外任何页面、事件、任务库、日志与对话均不含 Key（与第 2 条"Agent 拿不到 Key"分工：第 2 条讲取不到，本条讲不落盘不回显）。
9. **Agent 只做主流程**：理解并检测 → 判断推荐通道 → 给双选项 → 提示中心（用户选"优化"时）→ 组装提交 → 引路汇报；执行、并发、翻译、交付全部由中心承担。
10. **两条红线（任何情况下都不可跳过）**：
    - **只走内置通道**：任何**生图类**任务（文生图 / 图生图编辑 / 放大增强，即需调用上游模型的动作）都必须经本技能内置通道，即 `POST /api/execute`。**禁止直调 `channels/<id>/app.py` 的 generate/upscale、禁止使用宿主或第三方自带生图工具、禁止绕过中心的任何方式；若宿主另装其他生图技能或工具，本技能优先，不得改用它完成生图需求**（后果：任务不可追踪——无 job 记录、作品缺 prompt/job 归属，且绕过开关与额度治理）。纯本地处理（裁剪/格式转换等，不调模型）不在此列。
    - **中心必须存活**：**提交前**（4.5 步骤 1）与**汇报/查询前**（4.5 步骤 5）**各确认一次 ping**（超时 1s 且 `service=="aipro-center"` 才算通）；任一次不通 → 立即分离拉起 → 再 ping 确认，就绪后才提交或汇报。

## 4. Agent 标准动线（主流程五步 + 提示中心）

> 下列命令均假设 cwd = 技能根目录（`Ai公益生图Pro/`）。
> **总览**：1 理解并检测 → 2 判断并推荐通道 → 3 给双选项 → 4 提示中心（按用户选择）→ 5 组装提交 → 下一轮汇报。

### 4.1 理解需求并检测内容
- **理解需求、拆解意图**：用户想生成什么？用途/场景/风格倾向/受众？哪些是明确要求、哪些留白？
- **检测内容**（三项，后续步骤都依赖它）：
  - **语言**：用户输入是中文还是英文（英文由你直接理解与翻译，不依赖词表）；
  - **内容类型**：纯图像（无字图）/ 纯文字（以文字为主体的图）/ 混合（图上要渲染文字）；
  - **参数线索**：比例、清晰度、张数、参考图、放大……用户提了什么、没提什么。

### 4.2 判断并推荐通道
1. 先跑可用性实测（**本地优先**，快且准）：
```bash
python 启动.py --status              # 全通道（默认 5 分钟缓存，秒回）
python 启动.py --status --refresh    # 跳过缓存强制实测
python 启动.py --status <id> --refresh  # 查单通道并强制实测（4.6 轮询等待必须带 --refresh）
```
   - stdout 只有一行机器 JSON：`{"suggest": "<首个可用通道id|null>", "channels": [{"id", "title", "credential", "valid", "enabled", "models": [...], ...}]}`（以 stdout JSON 为判断依据，退出码为辅；`models` 非空时即该通道可选模型清单，见 4.3 模型选项）。**`--status` 是本地进程直跑，不代表中心已启动**——中心存活另按 4.5 步骤 1 判定。
     **`suggest` 只有两个用途**：①用户明确选 `auto` 时的路由目标 ②选项排序参考——**它不是替用户做的选择，禁止直接填进 `spec.channels` 提交**。
2. **按 4.1 检测结果分析通道**（内置特性知识；本地实测+特性仍存疑才联网查上游现状）：
   - 图上要中文文字（混合/纯文字）→ 智谱（须选付费档 `cogview-4-250304`）/商汤（须选 `sensenova-u1.5-fast`）/aurora(gpt-image) 更稳；
   - **语种铁律**：以各通道 **`CAPS.lang` 声明**为唯一事实源（实时查询 `python -m core.lang --cid <id> --prompt "<提示词>"`）：声明 `en` 的通道（Flux 系）收到中文会显著掉质 → **优化提示词时务必把中文转成英文再提交**；若用户要图上中文文字，改推智谱/商汤/aurora（Flux 渲染中文文字弱）；智谱/商汤中文更稳、aurora/agnes 中英皆可；
   - **Flux 提示词技巧**（cloudflare/free）：①把最重要的主体/概念**前置**（Flux 对靠后概念权重下降）；②不需要图上文字时追加 `no text, no logo, no watermark, clean background` 防伪字/伪 logo；③避免中文文字（见上），用留白后期叠字；
   - 改图/放大 → aurora/agnes/商汤（free/cloudflare/zhipu 不支持，会被自动过滤并说明）；**已注册的自定义中转通道支持改图（i2i）但不支持放大**；
   - 快速免费无特殊要求 → free/agnes。
3. **给出推荐通道与理由；但以用户选择为准**——推荐仅供参考，绝不替用户决定。
4. **用户已点名通道**（如"用 agnes 画…"）→ 跳过推荐，只跑 `--status <id>...` 验证通道可用（多选时一条命令查全部选中通道，stdout 各带 `models` 清单）；**并按需求核对能力与语种**（改图需 i2i、放大需 upscale——见通道表；语种按通道 `CAPS.lang` 声明，`python -m core.lang --cid <id> --prompt "<提示词>"` 实时可查——声明 en 的通道须转英文提交）：能力不匹配时**不提交**，直接告知原因 + 列出支持该能力的通道让用户重选（换通道必须用户重新选择，见 4.6）；4.3 的通道选项收敛为该通道，"是否优化"仍要问。

### 4.3 给双选项（呈现后等用户回复）
- **通道选项**（可多选，如「2、4」）。**呈现优先级：若宿主提供交互式选项组件（选择题/多选/表单），优先用组件一次弹出双选项——通道=多选题、"是否优化提示词"=单选题（默认"优化"）；宿主无交互组件时，才用下方文字渲染规范**；**两种形态都必须"停下等用户回复"，不得顺带提交**（数据全部来自 `channels`，不手工编造；**列出全部通道**——未配置/停用的也列并按实测状态标注，让用户看到全部选项；推荐理由仍只标在可用通道上）：

```
<序号>. <id> · <title>【<credential>·<有效|无效|未验>】—— <description 摘要>（无效/未启用的加注「选中将引导配置」）
```

真实示例（auto 是**路由策略项、非内置实通道**，仅用户明确选 auto 才启用并路由到 `suggest`）：

> 请选择生图通道（可多选，如「2、4」）：
> 1. auto · 自动路由【仅用户明确选择】—— 由我按当前可用性与你的需求自动选择通道
> 2. aurora · Aurora绮梦绘【需配置·未验】—— 文生图+图生图+增强放大；质量高至极高（选中将引导配置）
> 3. agnes · Agnes ai【内置Key·有效】—— 文生图+图生图+增强放大；出图快
> ...

- **通道选择红线**：**未拿到用户明确选择前，禁止提交**——不得把 `--status` 的 `suggest`、推荐结果或任何自定默认当作已选通道；**"默认即执行"只适用于下面的"是否优化提示词"这一项，通道选择没有默认值**（用户已点名通道＝已选择，按 4.2 第 4 点验证即可）。**模糊表态（"随便""你看着办""都行"）＝未选择，必须再问一轮，不得当作选择了 auto**（auto 仅在用户明确点名时启用）。
- **选中含无效/未启用通道**（单选，或多选中含）→ **不提交**，按 4.6 调起管理台引导用户配置 → 每 5~10 秒 `--status <id> --refresh` 重验至 `valid=true` → 再提交；用户明确不想配置 → 请其**重新选择通道**（绝不静默换）。多选时无效通道配置完成前整单等待（保持"一次交互全搞定"），不擅自先出部分。
- **通道带 models 清单（`--status` 中 `models` 非空，内置与自定义通道统一）→ 提供模型选项并说明默认**：清单 ≥2 个时，模型选项**并入同一轮交互组件问出**（多一道**多选题**：选项即清单、可多选、标注第一个为默认——**只选一个 = 用该模型；选多个 = 该通道按所选模型各出一张**）——不要让用户答两轮；**用户仅回复通道未选模型 → 视为不选（不传 model，服务端用默认），不追问、不阻断提交**。无论内置还是自定义通道，默认模型都是清单第一个（自定义清单 = 协议内置官网模型在前 + 用户注册补充在后）。**呈现模型选项时须读该通道 `channels/<id>/api.md` 标注免费/付费与权限依赖**（付费档须注明"能否使用取决于你自己的 Key 权限与账户余额"）；**无图上文字需求时一律按清单第一个默认（智谱即免费档 `cogview-3-flash`），不得因通道有付费档而默认付费档**；**图上要中文文字时，默认取该通道能渲染汉字的型号**（如智谱的付费档），并显式告知该型号为付费档——这一条优先于"清单第一个"的默认规则。**多选通道时一次性弹出**：对所有清单 ≥2 的**选中通道各出一道模型多选题**（并入同一轮组件，一次答完；清单 =1 的通道不问）——不要只对第一个通道弹。多通道并发时各通道 models 独立、`spec.model` 为单值会下发所有选中通道——用户要**逐通道指定不同模型**，或**模型多选题选了多个**（同一通道多个模型各出一张）→ 按模型拆成多条 spec 分别提交（每条 `channels` 单通道、各带其 model，`n` 保持该通道的张数语义缺省 1），提交前告知份数。
- **是否优化提示词？【默认：优化】**——用户不表态就按"优化"走 4.4；**"不优化"必须用户明说** → 跳过 4.4，`spec.prompt` = 用户原话（语言不动、不增不删，仅超长时提醒），直接到 4.5。**该默认在"收到用户回复、且未明说不优化"后才生效**——等待回复期间不得先行优化或提交。
- **upscale（放大）任务跳过"是否优化"提问**——放大不吃提示词，直接到 4.5 组装（可选 `upscale_prompt` 增强词）。
- **需求内容严重模糊时**（不知道画什么）：澄清问题与双选项**合并一轮问完**（不要让用户答两轮）——**仅限"需求内容"模糊；通道未选或表态模糊（随便/你看着办）仍按上一行再问一轮，不得当作已选择**。
- **不优化 + 通道与语言明显不匹配**（双向，**以通道 `CAPS.lang` 声明为准**：英文原话配声明 zh 的通道如智谱/商汤；中文原话配声明 en 的通道如 cloudflare/free——实时查询 `python -m core.lang --cid <id> --prompt <原话>` 看 `needs_conversion`/`flux_warning`）：按声明提示一次语种风险，用户坚持则原话直传。

### 4.4 提示中心（用户选择"优化"时进入）
- 完整流程见 `prompt_center/方法论.md`（**0 是否优化 → 1 供需审查 → 2 优化模式（匹配模板→判定 A/B/C）→ 3 分析参数 → 4 撰写提示 → 5 提示润色 → 6 质量审查**）。
- 产出 `spec.prompt` 与生图参数建议，回到 4.5 组装提交。本步只影响 prompt 文本与参数建议，通道方言仍由各通道 `translate` 处理。
- **变体交付**：**B 补全默认单主案直出**（不再额外等一轮）；仅 **A 创作**或**用户明确要"多风格/挑一挑"**时，才按方法论 4.5 先以文字方案呈现待选（选定后仅提交所选；说"都出"才全提交）。

### 4.5 组装 spec 并提交（提交后本轮无需等待生成结果；仍须按步骤 5 复查中心，且不得据此跳过 4.3 的等待）

| 字段 | 类型 | 说明 |
|---|---|---|
| `channels` | list | 用户选的通道 id；`["auto"]` 仅在用户明确选择时 |
| `prompt` | str | 生图提示词（generate 必填） |
| `action` | str | `generate`（缺省）或 `upscale`（放大增强） |
| `image` | str 或 list | 参考图（编辑，支持多张；**硬上限 ≤14**，各通道实际上限见 `CAPS.image_refs`：aurora 2 / 商汤·agnes 5 / 自定义 open 10、gemini 14，超出由协商层截断）/源图（放大）：本地路径或 URL；**upscale 必填** |
| `options` | object | 通道专属参数透传（如商汤去水印/输出格式、cloudflare 增强步数等） |
| `scale` | int | 仅 upscale：2 或 4 |
| `ratio` | str | 如 `16:9`（用户明示**或用途语义可推断**才传；推断的须在交付时声明） |
| `tier` | str | `1K/2K/3K/4K`（用户明示**或语义可推断**才传，如"高清"→2K；推断的须声明；**取值是否支持由通道按自身能力判定——不支持则就近降级（就近向上取通道最高档）并告知实际生效档位**） |
| `n` | int | 1~4（用户明示**或用途语义可推断**才传；推断的须在交付时声明） |
| `model` | str | 用户点名**或从 4.3 模型选项中选定**才传（见 4.3 模型选项规则）；**点名的模型不在该通道清单时，先告知可用型号请用户改选**——通道会明确报"模型不在该通道清单"，不会静默回落成别的模型 |
| `upscale_prompt` | str | 仅 upscale 可选：增强提示词（不传则服务端用"增强放大"） |

守则：**语义补全 + 只传支持的**——用户话里有质量/比例/张数线索就按语义传入（如"高清"→2K、"4K"→4K、"手机壁纸"→9:16、"来一组"→n=2~4；**注意：`n` 只表示"同一句提示词出多张"，"不同风格/不同构图"＝提示词不同＝必须分次各提交一条 spec，不可填 `n`**——见 `prompt_center/方法论.md 4.5`），什么都没提可不传；无论传不传，参数中心都会逐通道协商（不支持的自动就近降级，免费额度通道自动补体验档），Agent 无需知道各通道能力；未知字段会被服务端 400 拒绝。用途/线索 → 参数的完整映射与联动构建见 `prompt_center/方法论.md 3（分析参数）`；**spec 报 400 或需深挖协商降级机制时，再读 `references/architecture.md §4`**（日常按上表即可）。

提交：
1. **确保中心存活（红线）**：读 `~/.aipro/center.json` 取 port（缺文件用 8765）→ `GET /api/ping`（**超时 1s，且响应 `service=="aipro-center"` 才算通**——仅凭 HTTP 200 会误判端口被其他进程占用）；不通则**分离方式**运行 `python 启动.py` 拉起（Windows：`Start-Process python -ArgumentList '启动.py' -WorkingDirectory '<技能根>' -WindowStyle Hidden`；macOS/Linux：`nohup python 启动.py &`）——脱离对话轮次、不占轮次；**拉起后轮询 ping 最多约 5s**再确认，可用后才提交（中心不在则无法提交，作品也不会进作品中心）。
2. 提交（urllib 即可）：`POST http://127.0.0.1:<port>/api/execute`，body 为 spec；
   - `200 {"ok":true,"job_id","accepted","dropped"}` —— 立即返回，**生成在中心后台进行，Agent 本轮无需等待**；
   - `400 {"ok":false,"msg"}` —— **由你修正后重交：msg 指向参数就改参数、指向提示词就回 4.4（方法论 6.4）修；最多 2 轮，仍失败则原文转述用户并停止**（不靠改参数试探）；
3. `dropped` 非空时如实转述（如「aurora：需配置 Key」），涉及用户所选 → 按 4.6 调起管理台；
4. 结果中心已并入工作台第二屏（`/#works`）：**提交即自动定位作品中心**——工作台未打开 → 自动打开并直达该任务（`/#jobs-<id>`）；已打开 → 原地切换到作品屏并高亮新作品（**不新增页面**）；告知用户"出图实时看结果屏"即可。
5. **生成后复查中心（红线）**：提交后、以及**下一轮查询或汇报前**，都**再次 `GET /api/ping`**；不通 → 立即按步骤 1 的方式拉起 → 再 ping 确认 → 必要时 `--job <id>` 对账，然后才向用户汇报（并说明作品可在工作台 `/#works` 查看）——中心掉线则作品无法登记与实时展示，必须拉起后再汇报；**拉不起则如实说明并交还用户，不得改走其他生图方式**。

### 4.6 异常动线（不可用 → 调起管理台，绝不静默换通道）

- 先说明：无参 `python 启动.py` = 启动/唤醒中心服务（**管理台 console 与作品屏同属该服务**）——已有页面在线则**原地切到通道中心屏（不新增页面）**，未打开才新开。
- 用户所选通道 `valid=false`（选前）或任务中该通道 item 失败（结果页/`--job` 有服务端原文）→ **运行 `python 启动.py` 打开管理台**，引导用户在该通道卡片处理（获取/粘贴 Key 并验证，或清空走内置重验）；agnes 可在通道页登录自动回填；
- **原因分类处置**（按 `dropped`/服务端原文）：`通道已停用` → 引导用户在管理台卡片**打开该通道开关**再重验；`需配置 Key` / `凭证无效` → 引导配 Key（付费档需有权限的 Key）；`不支持图生图（编辑）` / `不支持放大（增强）` → **能力问题，配 Key 也解决不了**：如实告知原因 + 列出支持该能力的通道，请用户重新选择；额度/限流（402/429 等）→ 如实说明是额度或上游限流，可选等待重试或换通道（同样由用户决定）；`模型不在该通道清单` → 列出该通道可用型号请用户改选（通道会明确报错，**不会静默回落成别的模型**）。
- 轮询等待：每 5~10 秒 `--status <id> --refresh`（**必须带 `--refresh`**——默认 5 分钟缓存不带刷新会一直读到旧状态，永远等不到恢复；管理台重新验证也会即时刷新缓存），直到 `valid=true` → （重新）提交任务——选前无效是首次提交，执行中失败是重交；用户明确取消则终止并说明；
- **多选场景单通道失败只影响该通道**，其余通道结果照常交付，失败的通道走本动线；
- **绝不静默切换通道**——换通道必须用户重新选择。
- **重交范围 = 仅失败通道**：多选部分成功时，重提前先 `--job <id>` 核对，已 done 的通道**不得重交**（会重复出图）；全部通道不可用 → 如实说明"当前无可用通道"，引导配置后再来。
- **用户催促"怎么还没好"**：先查 `--job` 再回答，**绝不因此重复提交**。
- **进行中改需求**（"猫换成狗"）：已提交任务无法取消——如实告知旧任务会继续跑完，新需求按 4.1 重新走一轮（新提交）。
- **中心失联**：ping 不通 → 先拉起服务再 `--job` 对账；任务被中断就如实说，不假装成功。
- 轮询等待最多约 5 分钟仍未修复 → 如实告知进展，交还用户决定（不要无限占用轮次）。

### 4.7 下一轮汇报：`--jobs` / `--job` → 如实交付

```bash
python 启动.py --jobs            # 任务清单 JSON
python 启动.py --job <id>        # 任务详情 JSON（items/paths/error）
```

- 用户下一轮任意发言时查询：**先按 4.5 步骤 5（方法同步骤 1）确认中心存活**（不通先拉起），再 `--jobs` / `--job <id>` 查询：done → 交本地图片路径（可直接预览）；partial → 交成功部分 + 失败原文走 4.6；failed → 原文走 4.6；running → 告知进度，请用户看结果页。

## 5. 注意事项

1. **网络不可达的放行语义**：探活遇网络异常按"可用"放行，真实错误由执行暴露——失败时读 `--job` 的服务端原文，不要反复重跑 `--status`。
2. **上游现状（2026-10-15 实测）**：Pollinations 匿名档收紧情况见 1. 通道表 `free` 行（此处不重复）；agnes 上游强制单请求单张（多张自动走并发扇出，用户无感）。
3. **编辑图**需通道支持 i2i（free/cloudflare/zhipu 不支持，会被自动过滤并说明原因）；用户在通道中心注册的自定义中转通道支持 i2i（按其 CAPS 判定），但**不支持放大**（提交会被自动过滤并说明原因）。
4. **多通道并发安全**：通道间并行（上限 4）；同通道多张走 n 阶梯（通道 n → 扇出封顶错峰 → 降级串行），已由中心处理，Agent 无需关心。
5. **管理台生命周期**：配置/验证期间保持运行；中心服务常驻期间任务持续执行，关闭中心 = 停止后台生成。
6. **Key 的归属与安全**：Key 统一落 `~/.aipro/credentials.json`；不回显明文；用户在对话里给了 Key 时，引导粘贴进管理台对应通道卡片验证落盘。
7. **凭证换机**：`~/.aipro/credentials.json` 整文件迁移即完成。
8. **通道增删对 Agent 透明**：清单以 `--status` 实时输出为准；架构细节（依赖图/事件目录/任务 JSON/spec 字段/落盘）见 `references/architecture.md`（日常按动线即可，仅深挖时读）。
9. **产物目录**：图片**平铺直存**关联根并登记 `img.json`（命名 `通道_YYYYMMDD_HHMMSS_毫秒.ext`，人类可读可解析）；缺省 `桌面\Ai公益生图Pro\`，工作台 ⚙ 可运行时改关联（自动迁移），或 `config.ini [result] dir` 静态指定；中心 2s 轮询文件夹，外部增删图片实时同步作品中心（外来图/缺通道信息的图不显示）。
