# 提示中心 · 方法论（Agent 字典）
> 版本戳：AIPO-PROMPT-1.21.0（对齐主流程：0~6 步 + 附录 7 快速示例 / 8 代码对应）
> **读法**：主流程（SKILL 4.1~4.3）走完、用户选择"优化提示词"后才进入本文；按需查小节，每节可独立执行。
> 四条底线：尊重用户；**用户已给的字一个不动**（C 的表述微调除外，且必须说明改了哪里）；所有词表和对照表都是**示例不是限制**——你可以、也应该自己组织更好的表达；**凡是我补、改、猜的（补全内容、润色改动、推断的参数），交付时一句话向用户说明**。

---

## 0 是否优化（默认优化）
- 主流程 4.3 已问过用户。**默认＝优化**；用户明确选"不优化" → `spec.prompt` = 用户原话（语言不动、不增不删，仅超长时提醒），本文后续**全部跳过**。
- **该默认在"收到用户回复、且未明说不优化"后才生效——等待回复期间不得先行优化或提交**（与 SKILL 4.3 同口径）。

## 1 供需审查（先回审，再动手）
- 回到主流程（SKILL 4.1~4.3）复核一遍：**你对需求的理解对吗？内容类型（纯图像/纯文字/混合）判对了吗？通道推荐与需求匹配吗？**
- 有问题 → 从出问题那一步重走主流程对应步骤；有不懂 → **直接问用户，不要猜**。
- 复核无误才进入 2。

## 2 优化模式（先匹配模板找标尺，再判定 A/B/C）

### 2.1 匹配模板（找参照标尺）
- 内容类型命中模板库 14 场景（海报/公众号封面/文字图·日签/UI·信息图/电商/头像壁纸/社交配图/节日节气/编辑改图/演示教学/建筑空间/美食/漫画分镜/标注图解）→ 查 `prompt_center/templates/` 下对应文件（索引见其 README.md）；命中多个取**最贴近的 1~2 个**。
- 无对应模板 → 跳过本步，按 2.2 的通用判据直接判。

### 2.2 对照判定 A/B/C（模板是标尺，不是答案）
> 判据＝**信息完整度**：数一数用户明确给了几类**画面要素**（主体 / 风格 / 构图景别 / 光影 / 环境…）。**参数不计入 A/B 计数**——它只在判 C 时要求"无未决项"。
| 模式 | 什么时候用 | 怎么做 |
|---|---|---|
| **A 创作** | 信息很薄：**无主体，或只有主体/单一要素**（"画只猫""做个海报"）——创作空间大，由你全盘发挥 | 纯发散、创意性思维，自行创作全流程；**用户已给的词一个不动**（有主体也绝不偏离主体）；产出 1 主案 + 2~3 风格变体 |
| **B 补全** | **有主体 + 有维度**（"水彩风的猫""手机壁纸柯基"），但维度不够精细全面、描述与参数不够完整 | 扩展性思维：在用户框架内**补全**——缺的维度、更精细化的描述、参数构建，让画面更丰富、完善、美观；遇到影响出图质量的地方（如逆光人像却要五官清晰）**不回避、不改用户意图——用更专业、更聪明的描述引导模型智能化解与还原细节**（如补"轮廓光勾勒发丝边缘 + 柔和反射光照亮面部"，两全达成） |
| **C 原样** | **主体明确 + 画面维度覆盖好 + 描述具体成画面语言（不是空洞形容词），结构合理完善；生图参数无未决项**（用户没提的按 3.4 不传即可，不构成缺口） | 一字不动直传（语言也不动）；仅当原文有病句/歧义、明显影响模型理解时做**保义轻改，并向用户说明改了哪里** |

- **判定方法**：
  - **有模板**：拿模板骨架**逐项对照用户需求**——只有场景载体、内容全空 → **A**（模板当起跑架发散创作）；有主体+部分维度 → **B**（按模板补齐用户没给的）；**已达 C 标准（维度覆盖好、描述具体、无未决项）、甚至比模板更贴合 → C**（只改进不符合当前用户需求处，**绝不照抄模板**）。
  - **无模板**：画面要素 ≤1（无主体或只有主体）→ A；有主体+至少一个维度但未齐 → B；维度覆盖好、描述具体、参数无未决 → C。
- 拿不准：先补会不会**稀释用户已给的表达**？会 → 判 C；明显缺维 → B；薄到无从补起 → A。
- `--check` 返回的 `mode` 只是代码兜底猜测，**以你的判断为准**（可 `--mode` 显式指定）。
- 改图同三模式：A"保留X，改成Y"；B 保留原指令再补；C 原样/保义轻改。
- 选中的模板：**比例建议直接喂给 3 分析参数；版面骨架与文字规则供 4 撰写、5 润色使用**；一切以用户需求为准。

## 3 分析参数
依据：主流程（SKILL 4.1~4.3）的信息 + 2 选定的模式。

### 3.1 产出语言终判（确定性策略，已落地 `core/lang.py`）
> 语种识别与策略已代码化、可测试：`python -m core.lang --cid <通道> --prompt "<提示词>" [--mode C] [--cn-text]` 会回显 `detected/target/needs_conversion/flux_warning`，Agent 与中心均以此为准。

- **先按用户输入语言写**；**通道选定后**按下方策略终判（与联网调研一致：Flux 系英文更稳有论文佐证 arxiv 2508.14405；CogView/智谱中文原生；GPT-image 中英皆可但英文更一致）：

> 〔声明来源〕下表为各通道 **`CAPS.lang` 声明**的派生视图（唯一事实源 = 通道自治声明）；通道增删或声明变更时本表随实现同步，实时值以 `python -m core.lang --cid <id> --prompt "<提示词>"` 查询为准。

| 通道 | 目标语种 | 说明 |
|---|---|---|
| `cloudflare` / `free`（Flux 系） | **en** | 英文更稳；中文 prompt 经 Flux 会显著掉质，**必须转英文** |
| `zhipu` / `shangtang` | **zh** | 中文原生/更稳；英文可转中文 |
| `aurora` / `agnes` | 输入语言 | 中英皆可，保持用户输入 |
| `auto` / 未知 | 输入语言 | 随用户输入语言 |
| `u*` 自定义中转通道 | 输入语言 | 协议不定：open（GPT-image 系）英文更一致，gemini 原生中文亦可 |

- **多选通道语种冲突**：一条 spec 的 `prompt` 对所有通道共用，无法同时满足「Flux 要英文」与「智谱要中文」——**语种冲突时按通道拆成多条 spec 各提交**（每条 `channels` 单通道、各带其语种 prompt），与方法论 4.5「不同模型各出一张＝分次提交」同口径；不要为迁就某通道牺牲另一通道质量。
- **两条硬规矩（最高优先，覆盖上表一切）**：
  1. **图上要中文文字** → 提示词保持中文（即便选了 Flux 通道也保持中文；但 Flux 渲染中文文字弱，故**图上要中文文字时优先推荐智谱/商汤/aurora(gpt-image)**，见 SKILL 4.2）；**图上写什么字由你智能提炼**（从需求取合适短文案，**绝不把用户原话原样搬上图**，长句/口语直接上图必出乱码）。
  2. **C 模式连语言都不动**（优先于多选默认中文、通道策略等一切语言规则）。
- 自检：提交前用 `core.lang` 复核 `needs_conversion`；若 `flux_warning=true` 说明中文 prompt 将进 Flux——**先转英文再提交**（C 模式与图上中文文字两种硬规则除外）。

### 3.2 用途 → 参数对照表（示例，可按语义灵活判断）
| 用户提到/用途 | 参数 | 说明 |
|---|---|---|
| 手机壁纸/竖屏海报/小红书/故事配图 | `ratio=9:16` 或 `3:4` | 竖幅 |
| PC 壁纸/横幅/演示配图/视频封面 | `ratio=16:9` | 横幅 |
| 头像/电商主图/表情包 | `ratio=1:1` | 方图 |
| 公众号头图/宽幅海报 | `ratio=21:9`（整数比，或按用户说明就近） | 超宽 |
| 高清/清晰 | `tier=2K` | |
| 4K/超清/要打印/大幅面 | `tier=4K` | |
| 来一组/多几张 | `n=2~4` | 典型场景："同一张多出几张挑最好的"；**不同风格＝提示词不同＝多条 spec，提交前先告知用户份数**（见 4.5） |
| 改图/换风格/编辑 | `action=generate` + `image=<参考图>` | |
| 放大/增强/高清化 | `action=upscale` + `image` + `scale=2/4` | |
| 用户点名模型 | `model=<id>` | 通道专属参数 | `options` | 仅 open 协议自定义通道白名单生效（quality/background/output_format/output_compression/moderation）；gemini 协议 imageConfig 为封闭集，不透传 | |

> ratio 必须为**两端为正整数的整数比**（如 16:9、21:9，匹配服务端正则 `^[1-9]\d{0,2}:[1-9]\d{0,2}$`——0、前导零、小数会被 400 拒绝）；拿不准就选最接近的整数比。各用途的默认比例与版面骨架另见 `templates/` 目录对应文件（索引见其 README.md）。

### 3.3 参数和文字各管什么
- **数字比例（如 16:9）填进 `spec.ratio`**——规格由参数硬约束。
- 提示词里写**意图呼应**：构图语言 + 实际生效数值（如"宽幅构图、横向延展 16:9"）——参数管尺寸，文字管画面并强化意图，两者一致时模型遵循度最高。呼应写法见 4.1。

### 3.4 默认策略
- 用户没提的比例、清晰度、张数**不传**（不传≠用默认；免费通道服务端会自动补清晰度档）。
- 拿不准用途/比例 → 向用户确认，或声明默认假设后照做并告知。
- 口径：**3.2 用途映射＝用户已暗示**（如"手机壁纸"→9:16），按 3.2 传并在交付时声明；本节的"没提就不传"仅指**完全无线索**的情形。

## 4 撰写提示

### 4.1 八个部分，按顺序写（越靠前模型越重视）
`画幅构图 → 景别 → 主体外观 → 动作姿态 → 环境场景 → 光影 → 风格质量 → 留白`
- **画幅构图**指构图语言（竖幅/宽幅/方形构图），可带实际生效数值强化（见下方呼应表）；数字比例同时填 `spec.ratio`（见 3.3）。
- **景别放最前**（最容易被模型漏掉）：特写/中景/全景/航拍，前景/中景/背景层次、透视。
- **留白**：需要突出主体时写"留白、负空间、呼吸感"，让画面不挤——`_DIM_CHECKS` 已含此部分检查。

### 参数意图的文字呼应（双保险：规格由参数硬约束，文字再强化一次）
| 实际生效参数 | 文字呼应写法 |
|---|---|
| ratio 16:9 / 21:9 | `宽幅构图、横向延展 16:9` |
| ratio 9:16 / 3:4 | `竖构图、纵向延伸 9:16` |
| ratio 1:1 | `方形构图 1:1` |
| tier=4K | `4K 打印级清晰、细节锐利` |
| tier=2K | `高清细腻` |
| tier=1K | 不加质量词（不承诺做不到的细节） |
| n / scale / model / action | 不翻译——张数、放大是执行语义，没有画面内容 |

三条规则：
1. 数值一律用**实际生效值**（协商降级后的，如请求 16:9 被就近到 4:3，文字写"构图 4:3"）——文字与实际出图一致，不写做不到的数字；
2. 多通道共享一句提示词时，各通道生效值可能不同——**一致则带数值，不一致则只写构图语言、不带数字**（如"竖版构图"），否则文字与实际出图自相矛盾；
3. 服务端自动补的清晰度体验档**不呼应**（用户没提高清，文字不加；C 原样更是一字不动）。

### 4.2 把形容词换成具体描述（示例，可自创更好的）
| 用户说 | 换成 |
|---|---|
| 好看、精美 | 自然光线、有机形态、真实质感、材质纹理清晰 |
| 电影感 | 浅景深、宽银幕比例、青橙调色、胶片颗粒 |
| 背景虚化 | 浅景深 f/1.8、奶油般虚化、焦点清晰 |
| 清晰锐利 | 高解析度、细节丰富、边缘锐利 |

### 4.3 情绪用动作和表情细节表达
AI 画得出肌肉和动作，画不好"愤怒""开心"这类情绪标签：
- 愤怒/烦躁 → 咬肌绷紧、眉头拧结（`jaw clenched, brows furrowed`）
- 开心 → 眼角弯起、嘴角上扬（`eyes crinkled, open-mouth smile`）
- 注意：这条只管**你自己写/补的部分**；用户原文里写了情绪词就原样保留。

### 4.4 三种模式的具体做法
- **A 创作**：想清楚用途/场景/受众/风格 → 按 4.1 八个部分写全 → 追加真实感词（见 4.5）+ 图上要字则加中文文字要求 → 给 1 个主案 + 2~3 个变体。
- **B 补全**：先把用户已给的要求列出来（**一字不动**）→ 只补缺的部分（含 2 里说的"影响出图质量的隐患"修正）→ 追加真实感词 + 负向 + 需要则中文文字要求 → 自查补的内容与用户要求无冲突。
- **C 原样**：`spec.prompt` = 用户原文（或 2C 的保义轻改版），仅超长时按长度规则精简并说明。

### 4.5 按图类追加
- **真实感增强**（写实/摄影类追加）：自然光线、有机形态、不规则纹理、真实质感、生活气息——去掉"塑料感、蜡像感"。
- **写真人像追加**：面部受光均匀（不要一边亮一边暗）、皮肤干净哑光不泛油光、表情自然。
- **电影感/高级感追加**：材质真实可触、有空气感和景深、颜色克制不乱堆、构图大胆不对称、光影符合物理规律。
- **中文文字**（图上要出现中文字）：图上文案由你从需求**智能提炼**（短、少、清楚最宜，不是用户原话的搬运）+ 写明字体和排版 + 强制加 `文字清晰锐利，无重影无重叠，与背景对比鲜明`。
- **负向词**：代码 `negative_default()` 生成；spec 没有 negative 字段——中文提示词由代码**自动以"避免…"并入**；英文由你酌情并入。
- **改图**：按"保留什么 + 改什么 + 风格/材质约束"写，禁止只说"改一下"；**多参考图**：spec `image` 可传数组（硬上限 ≤14；各通道实际按 `CAPS.image_refs` 截断——aurora 2 / 商汤·agnes 5 / 自定义 open 10、gemini 14，第 1 张为主编辑图）——图1=主体保真、图2=背景/风格参考（超出通道上限由协商层自动截断，主图永远保留）。
- **多张/变体**：同一句提示词要好几张 → spec 的 `n`；不同风格的变体（提示词不同）→ 分次各提交一条。**交付节奏：B 补全默认单主案直出（不再额外等一轮）；仅 A 创作或用户明确要"多风格/挑一挑"时，才先以文字方案呈现待选**（选定后仅提交所选；说"都出"才全提交）。
- 命中模板库场景：用 2.1 匹配的模板骨架参考（`templates/` 目录），配合 3.2 定比例与中文文字要求。

### 4.6 构建句式
1. **先按任务复杂度选结构**（三档）：
   - 简单明确 → **极简直入**：名词短语/一句话（"傍晚海滩上的橘猫，电影感"）——倚靠模型自主发挥；
   - 常规需求 → **段落任务书**：任务句 → 主体构图 → 文字 → 光线材质风格 → 排除（比例走 spec）；
   - 复杂多块/批量 → **分节式或 JSON 网格**：角色前缀+分节标题（【标题区】【视觉…】）或逐格 JSON（position/shape/icon）——品牌 KV、信息图、图标集适用。
2. **任务句**：开头声明"数量 + 完成态 + 品类"（"生成一张完成的宣传海报"）；版面场景**显式排除过程性产物**（"单张成品，不要拼贴/草图/多方案"）。
3. **主次声明**：画面多元素时写一句"X 是主体，Y 只是点缀"——防主体错位。
4. **内容锚定**：图上文字用**引号/书名号包裹 + 位置 + 字体 + 尺寸四件套**，exact/逐字 + dominant 地位。
5. **细节展开**：按 4.1 八部分落成可渲染描述；写实类用"**缺陷即真实**"——写要什么瑕疵（指纹/噪点/次表面散射/手持噪感），比写"要真实"有效得多。
6. **排除项四类**：过程稿（拼贴/草图/多方案）· 风格污染（插画/CGI/动漫）· 画质缺陷（水印/乱码——负向自动并入勿重复）· **文化血统**（古风/节日类显式排除他文化元素混入）。

## 5 提示润色（表达层，让模型更懂意图）
- 4 已保证**结构完整**；本步只优化**说法**：通读一遍——消除歧义、术语更精准、语序更自然（重要信息放前面）。
- **与 2B 的分工**：B 补的是"内容"（缺什么），本步改的是"说法"（怎么更好懂）；**本步不新增画面内容**。
- 底线不变：用户原话里的关键词/要求不改；每次改动以"更好懂"为唯一目的。

## 6 质量审查

### 6.1 代码自动检查
```bash
python -m core.prompt_opt --check --prompt "<写好的提示词>" [--keep "<用户原话>"]
```
自动做：同义重复去掉 / 自相矛盾和与用户要求冲突的删掉 / 缺哪部分提醒 / 超长精简（中文 ≤200 字、英文 ≤1200 字符）。**B/C 模式下 `--keep` 必传（用户原话），否则你合法的增补可能被当冲突误删；返回的 clean 文本仅作参考，最终以你的文本为准——issues 才是重点。**

### 6.2 产出前自查（三条常见错误）
1. **形容词堆一起**：连续堆"高质量、精美、漂亮"却没有具体东西——换成 4.2 的具体描述。
2. **自相矛盾**：如"夜晚"配"烈日"、正向和负向打架、你补的内容跟用户要求冲突——去掉矛盾的那方。
3. **一大段没结构**：整句 50 字以上不带停顿——拆成短句、按 4.1 的顺序分段。
总原则：具体 > 模糊，一致 > 矛盾，精简 > 冗长。

### 6.3 质量评分
- `optimize()` 返回 `score`（0-100 ＝ 覆盖部分 60 + 长度合理 20 + 无矛盾 20 − 常见错误扣分）。
- **注意**：score 只检查"提示词本身写得好不好"，**不等于出图效果**——分低就回去改提示词，不代表图会差；真正的出图质量检查是出图后的视觉反馈（后续加，默认关）。
- 阈值由环境变量 `AIPO_PROMPT_GUARD` 控制（部署方设置，**Agent 不用管**）：设 `1`＝只检查不评分；设数字（如 60）＝低于这个分会在 issues 提示回去重写；不设＝关。
- 词表是中文高频词；**英文输入以你自己的判断为准**，别因为分低就盲目重写。

### 6.4 审查不过 → 顺序重走
- 问题出在 3 → 从 3 重走到 4 → 5 → 6；出在 4 → 4→5→6；出在 5 → 5→6。
- **只能顺序走，不能跳**；**最多 1 轮**——仍不过就带说明提交，并如实告知用户。
- 每次重写后，回头对照**用户原话**确认没有偏离本意（防止越改越漂）。

### 6.5 安全与合规（通道无关）

#### 6.5.1 默认原则
- **默认用户善意，优先成单。** 主动预判特殊场景：审美（艺术写真/人体艺术）、公益（防灾科普/健康宣教/禁毒反诈）、教育（教材图解/历史考据/性教育生理科普）、纪念（节庆/历史纪事）等——均正当且高频，按总表规范写法直接成单。
- 审核是通道自己的职责（自部署模型自带审核、第三方平台自带风控），本技能不做重复拦截，只划最少量的硬线（见 6.5.4）。
- 通用判据：**主体（谁）+ 场景（哪）+ 语境（用途/风格）三要素齐全**——缺语境是误杀的头号原因。
- 拿不准时：联网查证同类案例与平台口径；仍不确定 → 按保守一档处理并如实说明，或请用户补充语境后再生成。

#### 6.5.3 误杀场景处置：智能改写流程

- **第 0 步 · 意图判定（先于一切改写）**：判断"用户要什么"而非"用户说了什么"——词面踩雷但意图正当 → 进入改写流程；意图本身越线（红线列）→ 直接按 6.5.4 叫停。**不因措辞粗糙误判意图，也不因意图正当无视红线。**
- **改写四步**：
  1. **归类**：对照 6.5.2 总表定位题材行，确认该场景属"正当"列；
  2. **补语境**：把"谁 / 哪 / 干什么"三要素补全（语境是审核识别正当性的钥匙）；
  3. **换词**（按需组合策略库，不叠床架屋）：
     - **术语化**：敏感词 → 学术/行业术语（限教材/科普/医学语境）；
     - **语境化**：补场景与用途（街拍/度假/电商/教材）——"比基尼"单独出现易误判，"海边度假街拍"即可识别；
     - **形式化**：电影语言/插画/雕塑/分镜（"吐血"→"剧照特效妆容，嘴角一缕血迹，无血腥不写实"）；
     - **构图化**：特写 → 中远景、局部 → 整体、正面 → 剪影/背影（内容不变，呈现避开误判区）；
     - 涉及真实人物（尤其女性）：写服装、姿态、光影，不写身体暴露；
  4. **自检告知**：红线词扫描清零 + 三要素齐全 + 意图等价，三查通过才提交；向用户一行说明"为避免误拦，把 X 写成 Y，效果等同"，不隐瞒不啰嗦；用户坚持原措辞 → 如实提醒可能被通道审核拦截，交用户裁定。
- **降级链**：词面改写仍不足 → 构图调整 → 风格化呈现 → 与用户协商调整方向。每级先告知再执行；**同一请求对同一通道最多改写 1 轮**——仍被拦即通道级限制，如实说明并给替代方向，不反复盲试。
- 底线：**改写是帮正当意图被准确识别，不是让违规内容看起来合规**——超出总表"红线"列的行为直接按 6.5.4 叫停，不做改写。

#### 6.5.4 严格禁止场景（必须叫停）
- **政治人物图像**：中国国家领导人绝对禁止——无改写、无替代方案；外国政治人物一律同样拒绝（含影射、讽刺、虚构事件场景）。相邻正当仅：历史文化科普、民俗节庆、建筑风光（不含任何政治人物肖像）。
- **直接要求暴露隐私部位（性器官/胸部等，性倾向明显）**：叫停当前方向并说明原因；**同时必须主动给出替代方案**——时尚写真、艺术雕塑、剪影/背影构图等完全脱开性化的版本，由用户确认后继续。替代方案本身不得含任何性化表达。
- **其他直接违法犯罪倾向**（武器制造、毒品、诈骗、暴力威胁等）：立即停止并明确警告用户。
- **随任务附带提醒**：不生成侵权 Logo 与有版权角色，图上文字只写从用户需求提炼的内容；参考图含人脸仅本次使用、不留存不复用，他人肖像提醒先获授权；涉及商用提醒查阅对应通道条款（商用条款、AI 生成标识）。
