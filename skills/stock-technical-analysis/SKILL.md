# 个股技术面分析

## 核心心法

技术分析的本质是**概率评估**，不是预测未来。三条铁律贯穿全部分析：

1. **概率思维** — 图表反映"当前态势偏向哪种概率"，不提供确定性预测。所有结论以概率表述（如"偏多概率较高"而非"要涨"）。
2. **量价为本，指标为辅** — 价格与成交量是第一性数据，MACD/KDJ/RSI 均为衍生品。量价与指标矛盾时，信量价。
3. **风控保命** — 每笔分析必须包含止损位和仓位建议。止损位设在技术关键位，不是随意百分比。盈亏比低于 2:1 的交易不值得做。

## 数据获取（选股魔方 REST Skill API）

本 Skill 通过 `scripts/call_tool.py` 调用选股魔方 REST Skill API 获取行情与基本面数据。脚本内置 RFC 8628 Device Authorization（微信扫码授权），**不依赖 MCP**。禁止改用 MCP、PKCE、外部二维码网站或让用户粘贴 Token。

### 调用约定

```bash
python scripts/call_tool.py --tool <tool> --arguments '<json>'
```

- `--tool`：白名单工具名（完整清单与参数见 `references/tools.md`）
- `--arguments`：JSON 对象，字段使用 snake_case
- 可用环境变量：`XGMF_AUTH_BASE`、`XGMF_SKILL_BASE`、`XGMF_ACCESS_TOKEN`

### 退出码约定

| 退出码 | 含义 | 处理 |
|--------|------|------|
| `0` | 成功 | 读取 stdout JSON 的 `data` 字段 |
| `10` | 需要授权 | 将 stdout 中 `qrMarkdown:` 后的 Markdown 图片**原样**放入回复，让 skill client 直接展示微信小程序码；不要输出授权 URL 或让用户打开授权页面。提示用户扫码后**重新发送原请求**，并停止本轮调用 |
| `1` | 参数错误 | 不重试，检查 `--arguments` |
| `2` | 网络/服务错误或 Token 失效 | 最多重试一次；Token 失效时脚本会清理本地凭据并重新生成二维码，按退出码 `10` 处理 |

### 数据维度 → 工具映射

| 分析维度 | 调用工具 | 参数示例 | 说明 |
|----------|----------|----------|------|
| 证券代码识别 | `lookup_sec_id` | `{"keyword":"贵州茅台"}` | 名称/简称/不明确代码转标准 `sec_id`（如 `600519.SH`） |
| 基本信息快照 | `snapshot` | `{"sec_id":"600519.SH"}` | 价格、涨跌幅、换手率、量比、成交额等（⚠️ **无市值/股本字段**；`volume`/`mavol10` 单位为**股**非手，显示"万手"需÷100） |
| 股本结构（市值计算） | `company_f10` | `{"datasets":["CAP_LATEST"],"sec_id":"600519.SH"}` | 权威股本：`total_ashr`=总股本、`float_ashr`=流通A股、`free_float_ashr`=自由流通、`restricted_ashr`=限售；总市值=现价×total_ashr，流通市值=现价×float_ashr |
| 分时走势（日K聚合原料） | `trend` | `{"sec_id":"600519.SH","days":30}` | 逐分钟价格/量能/`ddx`；**按日聚合可得近30日日K**（open=当日首根分时price**≠pre_px**、high/low=`max_high_price`/`min_low_price`、close=末根）；⚠️ 实测（2026-08-21）：分时 `volume`/`value` 是**当日累计值**，聚合日K时**取每日末行**即全天总量（与 `snapshot` 完全一致），**切勿对全行 `sum`**（会虚增约×200）；每日换手率=末行 volume ÷ metadata.`mshare`（流通股本）；`days` 最大30；⚠️ `volume` 单位为**股**非手 |
| 周K线（≥52根） | `kline_range` | `{"sec_id":"600519.SH","period":"week","start":"20240101","end":"20260821"}` | 长期趋势判断；K线含 `ddx` 大单动向字段可佐证资金维度；`period` 支持 `week`/`month`/`season`/`year` |
| 板块/概念/行业 | `company_f10` | `{"datasets":["COMP_DETAIL","SW_INDUSTRY"],"sec_id":"600519.SH"}` | 公司资料、申万行业归属 |
| 融资融券 | `company_f10` | `{"datasets":["MARGIN_TRADE"],"sec_id":"600519.SH"}` | 杠杆资金动向（近5-10日） |
| 龙虎榜 | `company_f10` | `{"datasets":["STRANGE_TRADE_DT","STRANGE_TRADE"],"sec_id":"600519.SH"}` | 游资/机构动向（先查日期列表再查明细） |
| 市场信号 | `market_signal` | `{"sec_id":"000001.SH"}` | 市场宽度、量能、温度、情绪辅助判断 |

> **⚠️ 已知限制（2026-08-21 实测）**：REST 白名单的 K 线接口（`kline_range`/`kline_offset`）**不支持日K与分钟K**——`period` 传 `day`/`1d`/`daily`/`D`/`1day`/`1D`/`1W`/`1M`/`30m`/`5m` 及数字均返回 `参数异常`，仅 `week`/`month`/`season`/`year` 可用。**日K只能通过 `trend` 分时按日聚合获取（最近30个交易日）**，更早的日K历史标注"数据不可用"，不得用周K/月K冒充日K、不得编造。

> **缺失维度处理**：主力资金净流入明细、筹码分布等 REST 白名单未暴露的数据，标注"数据不可用"，**不编造、不用其他数据冒充**。资金维度可用融资融券、龙虎榜、量价关系、K线/分时 `ddx` 等替代证据佐证，并在报告中注明替代方式。

### 数据要求（分析前置）

分析前必须通过上述 API 获取以下数据（缺失的维度标注"数据不可用"，不编造）：

1. 个股基本信息（代码、名称、价格、涨跌幅、市值、流通市值、板块/概念）→ `snapshot` + `company_f10`
2. K线数据（周K≥52根、月K≥24根；日K用 `trend` 分时聚合近30日，`days` 最大30）→ `kline_range` + `trend`
3. 均线数据 → 周K/月K计算 MA(周)5/10/20/30、MA(月)5/10/24；日K仅近30日可算 MA5/10/20（MA60/120/250 如日K历史不足则标注"日K历史不足30日，长期均线以周/月线为准"）
4. 成交量与换手率（近20日明细）→ `trend` 聚合日K量字段 + `snapshot` 换手率
5. 技术指标（MACD、KDJ、RSI、BOLL 当前值及近5日变化）→ 优先用周K/月K计算；近30日日K指标（MA/MACD/KDJ/RSI/BOLL）用聚合日K计算并注明"近30日口径"
6. 资金流向（主力净流入、大单动向，近5-10日）→ `trend`/K线的 `ddx` 字段 + `market_signal` / `company_f10`（MARGIN_TRADE/STRANGE_TRADE），不可用则标注
7. 筹码分布 → 如 REST 不可用则标注"数据不可用"
8. 北向资金/融资融券（A股，如可用）→ `company_f10`（MARGIN_TRADE）

> 数组型行情数据必须先按返回的 `fields` 映射列，再作结论；说明证券标识、数据日期、复权方式和单位。`kline_range`/`kline_offset` 的日期参数必须用 `yyyyMMdd`（如 `20250101`），用 `2025-01-01` 会报解析错误。

## 分析流程（六层递进）

每层递进，前层结论约束后层分析。详细方法论见 `references/analysis-framework.md`。

### 第一层：个股基本信息
快速快照 — 代码、名称、价格、涨跌幅、市值、板块。明确分析标的。

### 第二层：多周期趋势嵌套
**周线定方向，日线找结构，60分钟定入场。** 高级别约束低级别：
- 周线上升趋势 → 日线回调 = 买点区域
- 周线下降趋势 → 日线反弹 = 卖点区域
- 周线震荡 → 日线高抛低吸

分析三个时间维度（长期/中期/短期），重点判断多周期是否共振。多周期共振的信号置信度远高于单周期信号。

### 第三层：关键价位定位
识别支撑与阻力：前期高低点、均线位置、跳空缺口、筹码密集区、黄金分割位。标注当前价格在关键价位中的位置（高位/中位/低位），计算到各关键价位的距离百分比。

### 第四层：五维交叉验证
五个维度互相印证，不是平行罗列：

| 维度 | 核心问题 | 权重 |
|------|----------|------|
| 趋势 | 往哪个方向走？强度如何？ | 25分 |
| 量价 | 方向有没有动能支撑？是否背离？ | 20分 |
| 指标 | MACD/KDJ/RSI/BOLL 辅助确认 | 20分 |
| 形态 | K线组合在表达什么意图？ | 15分 |
| 资金 | 主力资金在进场还是撤退？ | 20分 |

重点识别维度间的**背离信号** — 如趋势向上但量价背离，是强烈警示。

### 第五层：共振判断与评分
汇总五维结果做决策门控：
- **4-5维共振看多** → 高置信偏多，可考虑进场
- **3维看多** → 中等置信，等待确认
- **2-2-1分歧** → 信号矛盾，观望
- **4-5维共振看空** → 高置信偏空，考虑减仓/回避

给出 0-100 分技术面综合评分。评分体系见 `references/scoring-system.md`。

### 第六层：风控与操作建议
- **止损位**：设在技术关键位（支撑跌破点、趋势线破位点），非随意百分比
- **仓位建议**：金字塔分仓 — 试仓轻，对了加，错了砍
- **盈亏比**：计算目标收益/止损风险，低于 2:1 不建议操作
- **三种策略**：激进（首信号入场）、稳健（等确认）、保守（多重确认）

## 输出要求

1. 按 `references/output-template.md` 的固定模板输出结构化报告
2. 数据标注来源（选股魔方 REST API）和日期
3. **判断语气留余地**（强制）— 结论动词用"或/可能/疑似/建议/参考/暂看"，禁用"必/将/唯一/确认/无可争议/显然/目标位看/明确偏多/严重超买"。**结论性内容（各级结论、共振判断、总结框、核心一句话）同样必须走这套语气，不能正文软化、结论又变绝对**。详细规范见 `references/output-template.md` 的"判断语气规范"章节
4. **数据分层标注** — 接口直给数据不加标签；本地计算派生指标标注 `[计算]`；综合推断定性表述标注 `[推断]`
5. **交付前强制自检** — 按 `references/output-template.md` 的"数据准确性自检清单"逐项核对（单位、溯源、open≠pre_px、时序断言验证、语气终扫），任何一项不通过先修复再交付。**数据错误零容忍：单位错、开盘价错、无依据断言均属交付事故**
6. **成交量单位注意** — API 的 `volume` 字段单位为**股**（非手），显示"万手"时需 ÷100；`mavol10` 同理
7. **日K open ≠ pre_px** — `trend` 聚合日K时 open 应取当日首根分时 price，**不可用 pre_px（前收）替代**；如分时数据截断导致 high/low 不可用，需注明"日K high/low 为近似值"
8. **时序性断言需有据** — "拐头/金叉/死叉/背离"只在已计算指标时间序列时可用；只有终值时写当前值 + `[推断]`
9. **不可用维度不占行**（强制）— REST API 未提供的数据（如北向资金个股流向、筹码分布、超大单/大单分档买卖比例），**表格行直接删除**，不留"数据不可用 / 未提供"占位。仅在报告末尾"数据说明"区块用一行概括列出未覆盖的维度即可
10. **基本信息单表 + 三列布局**（强制）— 个股基本信息用**一张表**呈现（不按类别拆分子表），固定 3 列 `项目 / 数值 / 备注`；辅助信息（股本、实际换手率、口径说明等）放"备注"列，禁止塞进数值列的括号里
10. 必须包含风险提示和免责声明
11. 涨用红色，跌用绿色（A股惯例）
12. 聊天中给摘要，完整分析报告输出为自包含 HTML

## 常见误区

分析过程中需主动规避以下陷阱：
1. **单周期盲区** — 只看日线下结论，忽略周线大方向约束
2. **指标至上** — 把 MACD 金叉当买入信号，忽略量价是否配合
3. **确认偏误** — 只看支持自己判断的信号，忽视矛盾信号
4. **追涨杀跌** — 在价格已远离关键位时才给建议，盈亏比已不合适
5. **无止损入场** — 给买入建议但不设止损位
